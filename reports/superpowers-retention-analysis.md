# Superpowers retention analysis

Compound Engineering is the lifecycle owner. Superpowers bootstrap and global routing are disabled; native host discovery is the selection mechanism.

| Capability | CE equivalent | Decision | Exposure |
|---|---|---|---|
| `systematic-debugging` | `ce-debug` | retain as evidence/root-cause technique | supporting, non-automatic |
| `test-driven-development` | CE implementation/review gates | retain for explicit red-green-refactor discipline | supporting, non-automatic |
| `verification-before-completion` | CE proof/review gates | retain for verification discipline | supporting, non-automatic |
| `receiving-code-review` | `ce-code-review` | retain for review response technique | supporting, non-automatic |
| `writing-skills` | CE documentation/compounding | retain for skill authoring quality | supporting, non-automatic |

The lifecycle/routing set (`using-superpowers`, planning, execution, worktree, delegation, and branch-finishing skills) remains in the immutable package and is indexed, but is inactive in ordinary catalogs. The policy is recorded in `final-stack.yaml`, `docs/ce-superpowers-precedence.md`, and ADR-012.
